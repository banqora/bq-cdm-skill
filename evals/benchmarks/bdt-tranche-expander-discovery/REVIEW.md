# Reviewed result

This discovery variant was introduced because the earlier tranche-expander benchmark prescribed
the output topology and application sidecar so tightly that every arm scored 100/100. Here the task
described the business problem and required a genuine CDM 7.0.0 object, but left the Java API,
`Security` versus `TransferableProduct` decision, legal/economic boundary, builders, validation
strategy, and tests to the agent.

Four isolated, sequential arms were run from local Claude Max or ChatGPT subscriptions. Controls
could not read the skill, repository, historical benchmark, or sibling workspaces. Every arm passed
its authored suite from a clean offline copy before adaptive probes were added.

## Independent score

Claude Fable 5 independently read the frozen task and rubric, inspected all four deliverables and
traces, reran the suites, and probed generated CDM validation.

No fatal cap was applied. All four passed the requested examples but lost tap-provenance points
because they accepted a same-day duplicate as a reopening.

## What the skill changed

For Sonnet, treatment and control both chose a conservative generated `Security` plus an explicit
application envelope. The skilled result added a fuller `Asset -> Instrument -> Security` graph,
typed legal/currency values, structured failures, substantially more boundary tests, and a deeper
design record. Fable scored it eight points higher, but it used 76 rather than 66 tool calls and was
71% slower. This is a modest correctness/engineering win with excessive exploration cost.

For GPT-5.4, the skill changed the modelling outcome. Treatment used a generated
`TransferableProduct` with `Asset -> Instrument -> Security`, `EconomicTerms`, and an
`InterestRatePayout`, placing supplied coupon, maturity, issue date, size, and currency in coherent
CDM fields while keeping governing law and tap provenance application-owned. Its selected generated
data rules passed. The control used a thin `Security` wrapper, implemented the LEI checksum
incorrectly, invented unsupported `SENIOR` and `BULLET` facts, and duplicated the CDM dependency.
Treatment scored nineteen points higher with 50 versus 49 commands, although its wall time was 28%
longer.

The abstract `PARTY_1`/`PARTY_2` roles in the treatment product were not concrete trade-party facts:
CDM uses those roles as product-level indirection and binds concrete parties later. The defect was
that the design did not explain the required role election. Conversely, the Sonnet treatment's
claim that a `TransferableProduct` necessarily fabricates concrete trade parties overstated the
model boundary.

## Reusable improvement opportunities

1. Verify identifier/check-digit code against at least one independently sourced valid vector; do
   not test only with fixtures generated by the same algorithm.
2. Clarify that product-layer counterparty roles are abstract indirection, while requiring every
   role election to be justified rather than invented.
3. Require every populated CDM leaf to trace to source data, a model-mandated value, or a documented
   application assumption.
4. Name the validation tier actually run: cardinality/type-format, direct data rule, recursive
   graph validation, or qualification.
5. Turn the existing evidence budget into an operational limit: one batched declaration query and
   one batched Java-API query per owning layer, then compile the vertical slice.

These are generic CDM/application-boundary and efficiency lessons. The benchmark-specific
same-day-tap rule belongs in this evaluator, not in the skill.

## Post-run revision

After the result was sealed, the skill was revised to deep-link directly to a concise product-boundary
decision table; explain that product roles are abstract but still require justification; limit the
initial evidence pass to one combined declaration query and one combined Java API call; prohibit
searching root, home, or global caches for a runtime JAR; and require populated leaves and identifier
vectors to have independent provenance. The Java API helper now repeats that cache-scavenging guard
when its project runtime is absent. These changes post-date the four arms and are not credited in the
scores above.
